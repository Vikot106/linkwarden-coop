# 企业版需求实现核对与缺陷记录

核对依据为根目录的 [需求整理1.md](../需求整理1.md)，时间为 2026 年 10 月 26 日。当前已实现主要企业协作 MVP，但尚未满足全部最终验收项。以下状态区分代码实现、自动化验证和实际部署验收，不能将已有测试通过视为全部业务场景已验收。

本次检查包含权限计算、用户组与默认组、共享展示、协作编辑、删除、导入、标签、归档与相关前端查询。数据库测试只使用 `127.0.0.1:55432/enterprise_test`；根目录 `.env` 所指数据库未执行迁移。

## 本次修复的问题

| 问题 | 原行为 | 修复与证据 |
| --- | --- | --- |
| 删除贡献者导致共享链接丢失 | `Link.createdById` 使用级联删除，删除员工会删除其在其他人收藏夹中创建的链接。 | 改为 `ON DELETE SET NULL`，仅清空作者归属；收藏夹所有权的正常级联删除继续保留。数据库回归验证贡献保留、私人收藏夹正常删除。 |
| 删除企业资源所有者缺少保护 | 删除拥有部门或企业公共根收藏夹的用户，会级联删除企业资源。 | 账号删除前检查企业资源所有权，返回 409，要求先移交。所有权移交界面仍属于缺口，不能绕过保护直接删人。 |
| 删除账号失败却报告成功 | 删除事务异常被吞掉，仍返回 200。 | 失败返回 500，故障注入测试验证账号仍存在。 |
| 批量更新忽略缺失链接 | 缺失 ID 被跳过，其他项更新后仍报告全部成功。 | 校验请求结构与 ID 集合；缺失项在写入前返回错误。批量请求最多 500 项。 |
| 批量更新绕过客户端版本 | 用请求执行时读取的数据库版本替代用户原来看到的版本。 | 弹窗冻结打开时的链接版本并提交，服务端使用该版本，过期返回 409。共享链接批量更新缺少版本时也会拒绝。 |
| 收藏夹旧表单覆盖新内容 | 收藏夹名称、描述、公开状态及成员列表会被旧表单覆盖。 | 使用 `updatedAt` 做原子条件更新；共享收藏夹缺少修订信息、版本过期均返回 409，事务中的授权修改一并回滚。 |
| 并发移动产生父子循环 | 两个请求可能都在旧树上通过循环检查。 | 树移动在事务内持有 PostgreSQL advisory lock 并重查父链；相反方向的并发移动最多成功一个。 |
| 标签统计包含私人链接 | 共享和公开标签返回全局链接数量，按数量排序也会受私人内容影响。 | 列表、单个标签及公开标签统计按可见范围过滤；排序和游标分页使用可见数量。 |
| 删除收藏夹未完整回滚 | 外层事务中的删除实际使用全局 Prisma 客户端；根删除失败时子级已被删除。 | 子树删除、级联关系和所有用户排序清理统一放在同一事务；数据库提交后再清理归档和索引。数据库拒绝删除时，子收藏夹与链接保持完整。 |
| 轮询覆盖未保存的链接草稿 | 新数据到达会替换编辑中的内容；保存失败也会退出编辑。 | 编辑状态保留草稿及原始版本；保存成功才退出，冲突保留输入。DOM 交互测试覆盖其他编辑者更新后的草稿保留和保存冲突。 |
| 管理页面与详情停止更新 | 组和授权查询不轮询，归档完成后的单个链接详情也停止轮询。 | 管理查询和已登录链接详情使用 2 秒轮询，保留恢复网络刷新。编辑表单自身仍保留打开时的快照以防丢失输入。 |
| 多种导入事务无效或假成功 | Linkwarden、Pocket、Wallabag、Omnivore 导入在事务内使用全局客户端；部分格式吞异常，置顶导入没有等待完成。 | 全部改用事务客户端，数据库失败返回 500，置顶更新等待完成；逐格式故障注入验证收藏夹与链接均不留下部分导入数据。 |

测试位于 [企业需求回归测试](../apps/web/lib/api/enterprise.audit.integration.test.ts) 和 [链接编辑交互测试](../apps/web/components/LinkDetails.test.tsx)。原有权限与归档测试继续保留。

数据库与文件系统不支持同一事务。收藏夹删除提交后若归档或索引清理失败，会记录待重试信息；被删除链接无法再通过应用下载，但当前尚无自动补偿任务。账号删除原有的文件和计费外部副作用也仍需要更完整的补偿设计。

## 尚未实现和建议顺序

优先补齐资源所有权移交、部门管理员委派、共享根收藏夹的管理流程，以及来源和有效权限的明确展示。当前前端拖动移动仍偏向所有者，和后端管理权限能力存在差异。完整中文化也尚未完成：语言包已经补充，但 RSS 设置侧栏、详情查看/编辑标签、部分提示、下拉组件默认文案和部分日期格式仍有硬编码英文。

第二阶段尚缺：SSE/WebSocket 推送、授权变更审计、操作审计日志、收藏夹批量授权、用户组批量维护、授权记录的并发提示，以及容量和安全专项测试。已实现的批量组成员管理不等同于批量创建、修改和删除用户组。

第三阶段尚缺：身份提供商组信息同步、组织部门同步、离职流程自动撤权与资源交接、完整审计及企业备份恢复管理。已有 OIDC/Entra ID 登录提供商可继续使用，但并未与企业组授权自动联动。

上线前应先完成目标环境的完整镜像构建、备份恢复演练、真实浏览器协作与断网恢复测试、归档和附件回归、Meilisearch 集成，以及 50–100 用户规模的响应时间和同步延迟验收。

## 升级注意事项

新增迁移为 `20261026010000_preserve_shared_contributions`，只修改 `Link.createdById` 外键的删除行为，不重建数据表。已有企业迁移保持不变；总迁移数为 101。该迁移不能恢复升级前已经被级联删除的数据，此类数据需要从备份恢复。

正式部署前备份 PostgreSQL、附件和环境配置，再按 [企业部署文档](enterprise.md#部署和升级) 构建和更新。开发环境执行 `dev.cmd stop` 后重新 `dev.cmd start`，启动器会生成客户端并应用迁移。不要运行 `migrate reset` 或用 `db push` 代替迁移。

共享收藏夹更新请求应提交查询返回的 `updatedAt`，共享链接（包括批量编辑）应提交查询返回的 `version`。旧客户端缺少这些字段时会收到 409，应重新获取资源并更新客户端，不能直接重试覆盖。
